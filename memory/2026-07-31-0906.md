### Root Cause

LuCI Overview page reads `boardinfo.release.target` and `boardinfo.release.description` from the **ubus `system.board` JSON response**.

`procd` (system.c) reads `/usr/lib/os-release` and only parses these keys:
- `NAME` → `distribution`
- `VERSION` → `version`
- `BUILD_ID` → `revision`
- `OPENWRT_BOARD` → `target`  ← NEEDED for "Target Platform"
- `OPENWRT_RELEASE` → `description`  ← NEEDED for "Firmware Version"
- `OPENWRT_BUILD_DATE` → `builddate`
- Others → IGNORED (continue)

If `/usr/lib/os-release` is missing `OPENWRT_BOARD` and `OPENWRT_RELEASE`, the `release` table is empty → `boardinfo.release` becomes `{}` → LuCI shows undefined.

### The Offending Commit

`5df5c523b8 feat: add openwrt version customization templates for LuCI firmware display` (committed 2026-07-27) REPLACED the upstream OpenWrt os-release template (which has 19 lines incl. OPENWRT_BOARD/OPENWRT_RELEASE) with only 4 lines (ID/ID_LIKE/VERSION/VERSION_CODE/PRETTY_NAME).

This commit removed the very fields procd needs to populate the JSON that LuCI reads.

### Where It Actually Matters

There are TWO locations:
1. `package/base-files/files/usr/lib/os-release` — base-files package template (sed-substituted at compile time)
2. `files/usr/lib/os-release` — rootfs overlay copied wholesale by `include/image.mk:431` via `prepare_rootfs(..., $(TOPDIR)/files)`

The overlay **overwrites** what base-files writes. So even fixing only `package/...` is meaningless — must fix BOTH.

`package/base-files/files/etc/os-release` is a SYMLINK → `../usr/lib/os-release`. Don't need to fix it separately.

### Correct Fix

Add back the upstream-standard fields but keep our custom format on `PRETTY_NAME` and `OPENWRT_RELEASE`:

```ini
NAME="%D"
VERSION="%V"
ID="%d"
ID_LIKE="lede openwrt"
PRETTY_NAME="%D %F by zuoxm | R%C"      ← custom
VERSION_ID="%v"
HOME_URL="%u"
BUG_URL="%b"
SUPPORT_URL="%s"
FIRMWARE_URL="%f"
BUILD_ID="%R"
OPENWRT_BOARD="%S"                      ← needed for Target Platform
OPENWRT_ARCH="%A"
OPENWRT_TAINTS="%t"
OPENWRT_DEVICE_MANUFACTURER="%M"
OPENWRT_DEVICE_MANUFACTURER_URL="%m"
OPENWRT_DEVICE_PRODUCT="%P"
OPENWRT_DEVICE_REVISION="%h"
OPENWRT_RELEASE="%D %F by zuoxm | R%C"  ← needed for Firmware Version
OPENWRT_BUILD_DATE="%B"
```

Note: Use `%F` for OPENWRT_RELEASE's date portion (full datetime YYYYMMDDHHMM) to match the user's "202601220726" target format.

## Lesson Learned

1. **ALWAYS grep upstream OpenWrt for the canonical template** before customizing files in `package/base-files/files/` — don't just delete fields you don't recognize.
2. **Both `package/.../files/` AND `files/` need to be fixed** — overlay wins.
